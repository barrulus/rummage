IMPLEMENTED RESOLUTIONS

F01 — Direct loaded-ID lookup, revision-keyed focused and bulk property caches,
hashed membership and pointer-based aggregation replace repeated full scans.
No cursor means no focused photo; a hidden inspector does no property work.

F02 — Metadata work returns changed IDs; the controller fetches and patches only
those records in place. Appending a page extends the collection without copying
the prefix. Discovery and topology changes still trigger appropriate refreshes.
Date-sensitive queries refresh at completion or a throttled interval; disappeared
IDs trigger reconciliation. Selection, cursor and collection storage regression
coverage checks the ordinary metadata-patch path.

F03 — Protocol text is bounded at UTF-8 boundaries and malformed incoming text
is rejected. Per-photo extraction/serialization failures finish their claims and
record outcomes without abandoning healthy members of the batch.

F04 — Add-source and restore share exclusion validation. Restore rejects invalid
settings atomically; explicitly adding an existing source updates its settings.

F05 — Schema upgrades reserve unique backup names, preserve earlier backups and
can retry after rollback. Schema-one and schema-two upgrades, forced failure and
retry, concurrent initialization and retained trash receipts are exercised.

F06 — Checked timestamp conversion preserves exact seconds/subseconds and file
identity. An unrepresentable nanosecond timestamp has an explicit validity flag;
Details and the inspector show an unknown marker rather than a wrapped date.

F07 — Album counts now match visible query results; retained associations have a
separate count and scoped review action. Replacement files are never silently
assigned the previous file's annotations or album membership.

F08 — Website, navigation and architecture/license wording describe bundled
previews and the sole optional Photo Library add-on. Generated links and staged
component ownership are checked, including base behavior after add-on removal.

F09 — New Photo Library controls, menus, dialogs, statuses, settings and preview
messages are extracted and translated in all seven shipped catalogs. User text,
protocol enums and technical backend/filesystem diagnostics are not translated.

F10 — Details caches flattened rows by folder identity and revision. Stable draws
and cursor movement reuse the cache; mutations and expansion changes invalidate it.

F11 — Watch registration, picker acceptance validation and directory availability
checks leave the UI thread. Startup and folder navigation avoid synchronous stat
and canonicalization probes. Unavailable tabs/history locations remain reachable
and display their asynchronous model error, allowing later retry. Subfolder
probes and the auxiliary properties watcher also use asynchronous registration.
Pending picker checks can be cancelled, edited or invalidated by navigation;
weak folder ownership avoids retaining a closed picker’s directory model.
Watch registrations are bounded and cancellable; adoption reconciles event gaps.

F12 — Bulk browser context, palette, restore, erase and drag paths use hashed
membership; drag classification stops when it has enough information.

F13 — The client consumes work's existing bounded metadata candidates. Four
results persist in one transaction with per-item error isolation; claims still
revalidate file identity. Pending lookup and receipt lookup are indexed; receipts
are backfilled on upgrade. Row tags/albums are enriched in batches. A lightweight
progress endpoint returns one relevant job plus aggregate paused/waiting/failed
counts, while Activity retains the detailed history endpoint.

F14 — Restore explicitly replaces scalar annotations and merges tags/albums.
The confirmation and guide explain this contract. Newly restored sources remain
unmonitored until explicit refresh, across restart; existing monitored sources
retain their state. Restore cancellation and watcher behavior have regressions.

F15 — Duplicate groups have stable next/previous pagination and an explicit
all-active-online-sources scope. Export and restore share the 256 MiB / one-million
photo ceiling; oversized export fails before replacing its destination. Photo
drag remains unavailable and now explains Copy/Cut then Paste in context. Total,
loaded and selected scope remain explicit; resource and safety bounds are retained.

F16 — CTest preloads the compiler-matched ASan runtime for the Python-hosted
migration suite. Leak checking is disabled only for that CPython host; other
sanitizer suites retain their normal configuration.

REDUNDANT HELPERS

Shared title-bar construction, mount completion navigation and row-reveal math
replace the three application/view clones. Archive-read protocol validation uses
the existing validator. The helper reaper starts only on the first actual request,
so an unused optional photo client does not create a reaper thread.

LIMITS AND BEHAVIOR TO RETAIN IN REVIEW

Already executing filesystem syscalls cannot be forcibly cancelled safely. A slow
mount can occupy a worker, and shutdown joins executing worker calls. UI dispatch
and cancellation do not wait on that syscall; retained registrations are bounded.
This is not a claim of finite shutdown time for a permanently stuck kernel call.

The collection retains its browsed prefix in memory. Offset queries, complete
selection summaries and explicit full refreshes still scale with collection size;
the changes remove unnecessary repeated work, not all large-library cost.
Photo drag remains a documented restriction; Copy/Cut then Paste is supported.
History display and request-size/helper safety limits remain documented in the guide.

Schema version is now 3. Automatic pre-upgrade backups preserve older catalogs;
older add-on binaries will not open the upgraded schema. Validation uses disposable
catalogs and originals, not the user's library. No remote push or deployment occurs.
