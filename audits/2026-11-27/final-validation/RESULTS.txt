SSHFS CONNECTIVITY AND IDENTITY

The controlled fixture uses real SSHFS/SFTP on localhost, 300 generated PNGs,
a private catalog and display. No user mount, photo, catalog or app was controlled.
Its measured snapshot predates the main integration; none of the later changes
modify the tested photo filesystem identity/worker/preview paths. See sshfs/RESULTS.txt
for exact source/binary hashes, conditions, traces and excluded harness attempts.

PASS: normal-cache transport reconnection, 30-second cache-expiry verification
and rescan retained all 300 actual file identities and five album memberships.
Loaded-grid navigation remained responsive during two eight-second real transport
stalls, including a full refresh. A dead mount showed photos offline while keeping
album memberships. All generated source-image byte hashes remained unchanged.

OPEN LIMITATION: cache-disabled/zero-TTL SSHFS and remount-induced identity churn
regenerated 200 of 300 inode numbers without changing image bytes. A rescan kept
300 active images but the test album changed from five visible members to zero
visible/five retained members. Relink refuses ambiguous identities and cannot
currently reattach these retained associations. No file or annotation was deleted.
This was NOT reproduced with normal SSHFS cache settings in the controlled test.
A general fix needs trustworthy content/server identity reconciliation, not simply
accepting changed inode numbers or weakening original-file deletion safeguards.

Do not describe this report as an unconditional remote-library pass. Server reboot,
physical network faults, authentication renewal and indefinitely blocked kernel
calls were not exercised. Small generated images test fault behaviour, not throughput
or memory performance of the user's large remote library.

REPRODUCTION

  cmake --build /tmp/rummage-remediation-build -j6
  __EGL_VENDOR_LIBRARY_FILENAMES=/run/opengl-driver/share/glvnd/egl_vendor.d/50_mesa.json \
    EGL_PLATFORM=surfaceless LIBGL_ALWAYS_SOFTWARE=1 \
    ctest --test-dir /tmp/rummage-remediation-build --output-on-failure -j3
Use the same driver/environment for /tmp/rummage-remediation-asan, adding
ASAN_OPTIONS=abort_on_error=1 UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1.
Run the two test suites sequentially: their process-name fixtures overlap.
Package and SSHFS reproduction scripts, exact sources and hashes are in their
respective subdirectories. Temporary host paths are evidence locations, not
