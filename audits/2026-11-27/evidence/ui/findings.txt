# Native UI audit — frozen 1dd23687

Scope: ordinary Browser navigation/panes/sidebar, collection-backed and filesystem views, selection, search/palette, QuickLook/InfoPane/Properties, settings and picker integration. No production edits. All fixtures and harness artifacts are under this audit directory. No user catalogs, mounts or desktop used.

## Findings

1. **P1 — rubber-band photo selection with no cursor invokes quadratic metadata work every frame (introduced on branch).** `src/views/src/folder.cpp:283–297` lets `select_band()` update selection without establishing a cursor. `photo_library.cpp:993–1000` uses all selected IDs when `properties(true)` has no focused photo, then for each loaded row linearly searches those IDs. `browser.cpp:4188–4191` does this every frame even with InfoPane hidden. Reproduction via public API: load collection, clear cursor, select_band({}, all indices), draw. Equivalent native trigger: begin rubber band in blank area before selecting a focused row. Expected: rendering cost tracks visible rows and selection summaries update once; actual: O(loaded × selected) every frame. Fix direction: use selected-ID set/snapshot index for bulk metadata and return no focused metadata when no cursor; cache focused properties by stable ID + row revision; skip snapshot construction when InfoPane hidden. Reproduced in the Release harness: hidden-InfoPane frame 36.52 ms at 10k and 1,072.69 ms at 100k; the properties(true) call itself took 1,300.96 ms at 100k including fresh selection synchronization.

2. **P2 — all photo frames linearly scan the entire loaded collection twice (introduced on branch).** `photo_library.cpp:212–221` finds focused JSON row by linear scan; `:993–1000` scans all rows again even for a singleton. Browser calls it unconditionally as above. Selection near the end and deep continuous scrolling scale up the cost. Public harness measures `properties(true)` separately from native Browser draw and shared views.

3. **P2 — Details rebuilds full flattened row list on every draw and many input events (inherited).** `details_view.cpp:94–109`, `:567`, `:586`; it copies a shared_ptr row for every entry, then scans from start for cursor index. Even with no expanded directories and 20 visible rows, work scales with all 100k entries. Blame dates to 0d10494f before branch base63ca25bc. Cache flattening by folder/expansion revision or use direct root indexing when no expansion. Measured direct Details median grows from 0.97 ms at 1k to 3.08 ms at 100k; this alone is not a severe frame-budget failure on this host, but it is avoidable O(N) work and exacerbates the controller cost.

4. **P2 — startup/session and picker operations still synchronously touch mount paths (inherited).** `browser.cpp:3806–3809,3848–3850,3857–3861` validates each restored folder on calling/UI thread; `browser.cpp:6442–6448` validates folder shortcuts synchronously. `file_picker.cpp:116–169` calls status/access per selected path, invoked directly by accept at :328. A slow/unresponsive SSHFS/FUSE path can therefore block window initialization or input. No real mount used; code-path finding, not a measured user-mount delay. Move these checks to cancellable workers, preserve visible unavailable-tab state, and do not block every tab on one bad mount.

5. **P2 — ordinary bulk file drag / all-folder context menus perform quadratic name membership scans (inherited).** `browser.cpp:2524–2528`, `:5243–5246`, `browser_palette.cpp:201–205`: loop all listed entries and `ranges::find` selected name vector. The drag loop continues even after folders_only becomesfalse. Existing Folder already has hashed `is_selected()`. Use that for full selection, or set captured names where scope is cursor-only. Static complexity finding; no filesystem actions performed.

6. **P3 — photo rows cannot be dragged to ordinary folders (introduced restriction).** `browser.cpp:5227–5230` explicitly rejects all collection rows in start_drag. Clipboard copy/cut does exist, so functionality has a workaround, but native gallery-to-folder drag has no visible explanation. Requires deliberate product decision rather than blindly enabling without stable identity guards.

## Existing protection / non-findings

- Native Grid and Column rendering visits visible rows, not every entry; Folder selection summaries cache until changed.
- Folder sniff batches are bounded64; collection rows with supplied MIME avoid filesystem sniffing.
- Most normal I/O and all image decoding/summary loading are asynchronous. Same-device drag stat runs on a worker (`browser.cpp:5592–5600`), not UI.
- Collection append/query completion guards generations; visible callback only enqueues async work; ColumnView defers notifications until the frame’s iteration ends.
- QuickLook changed-location key invalidates preview slots; unavailable originals remain cache-only; destructive identity gates remain separate from preview permissions. Offline latency regression is already covered at frozen HEAD.
- No evidence yet of retained-object leak. RSS growth alone will not be called a leak; allocator/GL caches and peak vs current RSS must be distinguished.

## Method

`build_harness.py` compiles only out-of-tree harness sources against existing build archives using that build’s generated include flags/link dependencies. `run_harness.py` isolates XDG roots (final runs preserve HOME), forces surfaceless EGL/software GL, writes CSV and stderr, timeout120s. Fixtures: generated metadata-only collection entries for shared views; real backend schema seeded with synthetic rows and paused metadata for controller. These are UI/model measurements, not network or image-decoding throughput. Columns/Grid/Details use actual native draw methods and renderer. No production code is patched or private members exposed.

Harness note: first smoke screenshot captured a default transient selection effect, so final timed Photo Browser harness disables motion and ambient effects explicitly. Debug means CMakeDebug; Nix compiler wrapper still supplies -O2. Release adds later -O3/-DNDEBUG. Do not label Debug unoptimized.

## Suggested priority

1. Remove per-frame full collection/property scans and eliminate the no-focused-row bulk fallback. Build an ID index and memoize snapshots by relevant revision; bulk aggregation should iterate selected snapshots once.
2. Avoid republishing/copying all loaded entries for each append/metadata refresh; preserve stable IDs with incremental rows or revision-aware snapshots. Folder-only100k refresh already exceeds one60Hz frame before controller JSON work.
3. Move synchronous restored-tab/picker path checks to workers and retain explicit unavailable states.
4. Cache Details flattened rows by revision and replace repeated selected-vector membership searches with set membership.
