Verified photo browsing fixes

27 November 2026 · local branch feat/photo-library · Source and binary provenance

The reproduced catalog allocator growth is fixed by reusing one query worker, moving JSON batches, and returning unused allocator pages after catalog work settles. Remote browsing now warms its cache with bounded work, serves known snapshot cache hits locally, and can show the current photo's smaller preview while its larger version loads.

Memory and cache policy

  • One application-owned catalog worker reuses its allocator arena across windows and queries. Canceled queued requests release captured data promptly.
  • After three idle seconds, the catalog worker attempts to return unused pages if malloc reports at least 64 MiB of free capacity. It does this once per activity burst, outside input and draw callbacks. Free capacity can remain high after those pages become nonresident; it is not an RSS counter.
  • The existing texture budget remains 256 MiB, with visible and pinned textures protected. This is a texture-cache budget, not a cap on the process, loaded catalog, helpers or GPU allocations.
  • Local cached-PNG lookup has one separate worker, prioritizing the inspector over grid probes; it never opens an original. Cache misses move to source workers. Inspector source work uses two reserved workers. At most two obsolete started inspector reads and four grid reads finish warming disk cache. Obsolete decoded pixels are discarded.
  • Known listing/catalog timestamps permit local disk-cache reads before contacting SSHFS. Changed-location and unknown-time entries retain current-file validation; offline entries never open originals. Snapshot mode trusts the latest listing/catalog metadata, so external changes require a source update, as for existing in-memory cached textures.
  • Smaller inspector previews require the same path, nanosecond timestamp, MIME and cache policy, and automatically upgrade. Disk-cache URI and second-resolution mtime checks remain unchanged.

Validation

  • Release: all 16 suites passed.
  • Address/undefined-behavior sanitizers: all 16 suites passed. Existing Python-host migration setup and fontconfig suppression remain in effect; optional external fixture checks retain their existing skips.
  • ThreadSanitizer: three randomized runs, 26 cases and 46,215 assertions each, no race diagnostics. The intentional-race control correctly failed. Scope: EventLoop/WorkerPool and lifetime/cancellation stress, not the whole renderer or helper stack.
  • 16 performance-metric tests passed, including progressive/full-tier separation, identity matching and deadline enforcement.
  • Regression coverage includes 1,100-row refresh/cancellation, album/selection/cursor preservation, bounded obsolete reads, progressive upgrade and cache-policy isolation. Same-size/exact-mtime inode replacement retains old tags and album associations on the old identity.
  • Every measured run exited successfully, every private catalog passed SQLite integrity checking, and the original photos, user catalog and mount configuration were unchanged by these tests.
